# Physical Data Model — Spec 003

**Source of truth**: Spec 002 APROBADA, con enmienda de `cliente.estado`.  
**Scope**: diseño físico; no contiene migraciones ni SQL ejecutable.  
**Entity count**: 16, sin entidades adicionales.

## Conventions

- Esquema de negocio: `public`; helpers privilegiados: esquema privado no expuesto.
- Nombres en minúsculas y `snake_case`.
- PK ordinarias: `integer generated by default as identity`; crecimiento alto: `bigint identity`.
- Tiempos de hechos: `timestamptz`, generados por servidor.
- Valores decimales: `numeric` exacto; la aplicación no usa float para persistencia.
- Texto obligatorio: NOT NULL y CHECK de contenido no vacío cuando corresponda.
- Estado maestro: `boolean NOT NULL DEFAULT true`.
- Todo FK se indexa salvo que ya sea el primer componente de PK/UNIQUE útil.
- No hay `sector_actual_id`, `responsable_actual_id`, `cantidad_pisos`, `duracion_sector` ni
  `gramaje_id` en `ot_detalle`.

## Entities

### 1. `cliente`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | integer identity | PK |
| `nombre` | text | NOT NULL, no vacío |
| `telefono` | text | NULL |
| `correo` | text | NULL; formato se valida en aplicación, sin asumir unicidad |
| `estado` | boolean | NOT NULL, DEFAULT true |

Referencias desde `orden_trabajo`: ON DELETE RESTRICT. La operación normal es inactivar. Índices:
nombre para orden/prefijo si las consultas lo justifican y parcial por Activos para selecciones.

### 2. `orden_trabajo`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | integer identity | PK interna |
| `codigo_ot` | text | NOT NULL, UNIQUE, default desde secuencia dedicada, inmutable |
| `cliente_id` | integer | NOT NULL, FK cliente RESTRICT |
| `fecha_ot` | date | NOT NULL |
| `cantidad` | integer | NOT NULL, CHECK > 0 |
| `tipo_trabajo_parametro_id` | integer | NOT NULL, FK parametro RESTRICT; grupo validado |
| `cantidad_paginas` | integer | NULL o CHECK > 0 |
| `nombre_trabajo` | text | NOT NULL, no vacío |
| `estado_ot_parametro_id` | integer | NOT NULL, FK parametro RESTRICT; default resuelto a PENDIENTE |
| `idempotencia_creacion` | uuid | NOT NULL, UNIQUE; clave técnica durable de la creación agregada, no visible al usuario |
| `terminado_en` | timestamptz | NULL; obligatorio solo en TERMINADO y NULL en los demás estados |
| `anulado_en` | timestamptz | NULL; obligatorio solo en ANULADO y normalmente NULL en los demás estados |
| `creado_por_perfil_id` | integer | NOT NULL, FK perfil RESTRICT |
| `modificado_por_perfil_id` | integer | NULL, FK perfil RESTRICT |
| `creado_en` | timestamptz | NOT NULL, DEFAULT now() |
| `modificado_en` | timestamptz | NULL; token de concurrencia optimista |

Índices: UNIQUE código y UNIQUE `idempotencia_creacion`; `(fecha_ot DESC, id DESC)` para cursor; `(estado_ot_parametro_id, fecha_ot
DESC, id DESC)`; `(cliente_id, fecha_ot DESC, id DESC)`; FKs de perfiles y tipo de trabajo. El
estado se valida por código funcional, no por ID fijo.

`idempotencia_creacion` identifica el intento lógico de creación, no la OT para fines empresariales.
La operación servidor exige una clave estable, compara el intento repetido y retorna el agregado
canónico ya creado cuando coinciden clave y solicitud, sin insertar otra OT. La clave no reemplaza
`id`, `codigo_ot`, locks ni las precondiciones de otras operaciones.

Correlativo: secuencia independiente convertida a texto decimal, sin prefijo/relleno inventado. Una
futura importación privilegiada deberá comprobar unicidad y adelantar la secuencia por encima del
máximo código numérico importado.

| `tamano_material_x/y` | numeric | NOT NULL, cada valor > 0 |
| `armado` | integer | NOT NULL, > 0 |

| `total_pliegos` | integer | NOT NULL, > 0; dato registrado |
| `colorimetria_parametro_id` | integer | NOT NULL, FK parametro RESTRICT, grupo COLORIMETRIA |
| `cara_color` | text | NOT NULL, CHECK ANVERSO/REVERSO/AMBAS |
| `impresion_parametro_id` | integer | NOT NULL, FK parametro RESTRICT, grupo IMPRESION |
| `maquina_id` | integer | NOT NULL, FK maquina RESTRICT |
| `muestrario_parametro_id` | integer | NOT NULL, FK parametro RESTRICT, grupo MUESTRARIO |
| `tamano_final_x/y` | numeric | ambos NULL o ambos > 0 |
| `tamano_corte_x/y` | numeric | ambos NULL o ambos > 0 |

| `creado_por_perfil_id` | integer | NOT NULL, FK perfil RESTRICT |

Un trigger de constraint diferible valida al confirmar la transacción que los pisos de cada OT sean
exactamente `{}`, `{1}`, `{1,2}` o `{1,2,3}`. La RPC valida antes para dar errores comprensibles; el
trigger omite la comprobación cuando la OT padre ya no existe por una eliminación permitida.
Índices: UNIQUE `(orden_trabajo_id, numero_piso)` y FKs restantes.

### 4–7. Materiales y recursos

| Entidad | Campos y tipos | Constraints y referencias |
|---|---|---|
| `tipo_material` | `id integer identity`; `codigo text`; `nombre text`; `requiere_gramaje boolean`; `estado boolean=true` | PK; código UNIQUE/no vacío; nombre no vacío; RESTRICT desde material |
| `material` | `id integer identity`; `tipo_material_id integer`; `codigo text`; `descripcion text`; `estado boolean=true` | PK; código UNIQUE; FK tipo RESTRICT; descripción no vacía; RESTRICT desde piso/gramaje |
| `gramaje` | `id integer identity`; `material_id integer`; `valor numeric`; `estado boolean=true` | PK; FK material RESTRICT; valor > 0; UNIQUE `(material_id, valor)` |
| `maquina` | `id integer identity`; `nombre text`; `estado boolean=true` | PK; nombre UNIQUE/no vacío; RESTRICT desde piso |

La configuración material–gramajes se guarda atómicamente. Si el tipo requiere gramaje, un material
Activo debe tener al menos un gramaje Activo; si no lo requiere, puede tener cero. Trigger diferible
respalda la regla. No se agrega `gramaje_id` al piso. Códigos/estado y todos los FKs se indexan.

### 8. `parametro`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | integer identity | PK |
| `grupo_codigo` | text | NOT NULL; grupo aprobado |
| `valor_codigo` | text | NOT NULL; código estable |
| `descripcion` | text | NOT NULL, no vacía |
| `estado` | boolean | NOT NULL, DEFAULT true |

UNIQUE `(grupo_codigo, valor_codigo)`. Grupos cerrados: TIPO_TRABAJO, COLORIMETRIA, IMPRESION,
MUESTRARIO, ACABADO y ESTADO_OT. Códigos usados no se reciclan. Triggers de validación comprueban el
grupo esperado para cada FK, porque una FK simple por ID no puede hacerlo.

### 9. `ot_acabado`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `orden_trabajo_id` | integer | PK parte 1, FK OT CASCADE |
| `acabado_parametro_id` | integer | PK parte 2, FK parametro RESTRICT, grupo ACABADO |
| `posicion` | text | NULL o IZQUIERDA/ARRIBA |
| `creado_por_perfil_id` | integer | NOT NULL, FK perfil RESTRICT |
| `creado_en` | timestamptz | NOT NULL, DEFAULT now() |

La PK evita repetición. Trigger/RPC exige posición para PERFORADO, ENGOMADO, ANILLADO y ENGRAMPADO;
para cualquier otro código exige NULL. Índices adicionales: acabado y actor.

### 10. `rol`

|---|---|---|
| `id` | integer identity | PK |
| `codigo` | text | NOT NULL, UNIQUE; ADMINISTRADOR o USUARIO en MVP |
| `nombre` | text | NOT NULL, no vacío |
| `estado` | boolean | NOT NULL, DEFAULT true |

Referencias desde perfiles: RESTRICT. Las reglas consultan `codigo`, nunca un ID físico.

### 11. `perfil_usuario`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | integer identity | PK |
| `auth_usuario_id` | uuid | NOT NULL, UNIQUE, FK auth.users RESTRICT |
| `rol_id` | integer | NOT NULL, FK rol RESTRICT |
| `sector_id` | integer | NULL, FK sector RESTRICT |
| `estado` | boolean | NOT NULL, DEFAULT true |

Trigger/operación controlada valida: USUARIO Activo requiere sector Activo; ADMINISTRADOR puede tener
sector NULL; existe como máximo un perfil Activo con rol USUARIO por sector. Para serializar el
cambio se bloquea primero la fila sector. No se usa un índice parcial dependiente de un ID de rol.
Índices: auth UUID único, rol, sector y parcial sobre perfiles Activos.

### 12. `sector`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | integer identity | PK |
| `codigo` | text | NOT NULL, UNIQUE, estable |
| `nombre` | text | NOT NULL, no vacío |
| `orden_flujo` | integer | positivo y único entre participantes; NULL fuera del flujo |
| `participa_flujo` | boolean | NOT NULL, DEFAULT false |
| `estado` | boolean | NOT NULL, DEFAULT true |

CHECK une `participa_flujo=true` con orden positivo y `false` con orden NULL. Índice UNIQUE parcial
para `orden_flujo` participante. Referencias históricas RESTRICT; los sectores se inactivan.

### 13. `responsable_sector`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | integer identity | PK |
| `sector_id` | integer | NOT NULL, FK sector RESTRICT |
| `nombre` | text | NOT NULL, no vacío; no único global |
| `estado` | boolean | NOT NULL, DEFAULT true |

Índices `(sector_id, estado, nombre)` y FK. Cambiar de sector después de tener historia no está
permitido: se inactiva y se crea el registro apropiado.

### 14. `movimiento_ot`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | bigint identity | PK |
| `orden_trabajo_id` | integer | NOT NULL, FK OT RESTRICT |
| `sector_origen_id` | integer | NULL solo para INICIO, FK sector RESTRICT |
| `sector_destino_id` | integer | NOT NULL, FK sector RESTRICT |
| `responsable_sector_id` | integer | NOT NULL, FK responsable RESTRICT |
| `realizado_por_perfil_id` | integer | NOT NULL, FK perfil RESTRICT |
| `tipo_movimiento` | text | INICIO/AVANCE/DEVOLUCION |
| `ocurrido_en` | timestamptz | NOT NULL, DEFAULT now() |

Append-only: sin UPDATE/DELETE operativo. La RPC verifica primer origen NULL, origen igual al último
destino, destino diferente, matriz, estado, sector/responsable Activos y actor. No existe motivo.
Índices: `(orden_trabajo_id, ocurrido_en DESC, id DESC)` incluyendo destino/responsable si la versión
lo soporta y medición lo confirma; destino/fecha; responsable/fecha; actor/fecha.

### 15. `auditoria_evento`

### 16. `auditoria_cambio`

| Campo | Tipo físico | Reglas |
|---|---|---|
| `id` | bigint identity | PK |
| `auditoria_evento_id` | bigint | NOT NULL, FK evento RESTRICT |
| `atributo_codigo` | text | NOT NULL |
| `valor_anterior` | jsonb | NULL según operación |
| `valor_nuevo` | jsonb | NULL según operación |

UNIQUE `(auditoria_evento_id, atributo_codigo)`. Los valores pueden ser NULL según
CREATE/UPDATE/DELETE y se omiten atributos sin cambio relevante.
No DML operativo. La relación no depende de ninguna OT ni registro maestro.

## Referential Policy

| Relación | Acción al borrar padre | Motivo |
|---|---|---|
| OT → detalle/acabado | CASCADE | Solo ocurre en eliminación aprobada y borra dependencias operativas |
| OT → movimiento | RESTRICT | Una OT con movimientos nunca es eliminable |
| OT/maestros → auditoría | Sin FK | La auditoría sobrevive al registro |
| Auditoría evento → cambio | RESTRICT | Evita cascada accidental; ambas tablas son inmutables |
| Maestros/perfiles/sectores/responsables → historial | RESTRICT | Se inactivan, no se destruye historia |
| Perfil → Auth | Auth user RESTRICT por perfil | Inactivar cuenta conserva el vínculo histórico |

## Cross-row and Cross-table Enforcement

| Regla | UX/application | RPC | Constraint/trigger |
|---|---|---|---|
| Pisos 0..3 consecutivos | reducer no crea huecos | valida agregado | UNIQUE/CHECK + trigger diferible |
| Pares X/Y | error inline | valida payload | CHECK |
| Material requiere gramaje | filtra/explica | guarda configuración atómica | trigger diferible |
| FK al grupo parametro | filtra grupo | valida códigos | trigger de grupo |
| Acabado/posición | campo condicional | valida código | CHECK + trigger |
| Un USUARIO Activo por sector | muestra ocupación | bloquea sector/valida | trigger de respaldo |
| Movimiento | acciones permitidas | autoridad transaccional | FK/CHECK + DML revocado |
| Eliminación OT | confirmación | autoridad transaccional | RESTRICT/CASCADE selectivos |

## State Transitions

| Estado actual | Operación | Estado resultante | Condiciones |
|---|---|---|---|
| inexistente | crear | PENDIENTE | ADMINISTRADOR, cliente/tipo Activos e `idempotencia_creacion` única/estable |
| PENDIENTE | primer movimiento | EN_PROCESO | ADMINISTRADOR, destino/responsable válidos |
| PENDIENTE | anular | ANULADO | ADMINISTRADOR, sin motivo obligatorio; fija `anulado_en` atómicamente |
| PENDIENTE | eliminar | inexistente | ADMINISTRADOR y cero movimientos |
| EN_PROCESO | avance/devolución | EN_PROCESO | actor/sector/matriz válidos |
| EN_PROCESO | finalizar | TERMINADO | sector actual PRODUCCION y actor autorizado |
| EN_PROCESO | anular | ANULADO | ADMINISTRADOR; fija `anulado_en` atómicamente |
| TERMINADO/ANULADO | corrección excepcional | mismo estado | ADMINISTRADOR, auditoría completa, sin movimiento |

No existe transición normal desde estados terminales. `terminado_en` se establece por servidor junto
con `TERMINADO` y cierra su última permanencia; `anulado_en` se establece por servidor junto con
`ANULADO` y cierra la última permanencia productiva cuando existe. Correcciones administrativas
posteriores no cambian esos momentos terminales. No se persiste `duracion_sector`.

## Read Models and Index Validation

- `vista_ot_situacion_actual`: vista `security_invoker` con último movimiento por orden temporal
  total; NULL antes de INICIO.
- `vista_recorrido_ot`: puede usar `lead(ocurrido_en)` para duración de visitas cerradas,
  `terminado_en` para la última visita terminada y `anulado_en` para la última visita anulada; para
  una OT aún en proceso usa el momento de consulta. No persiste duración.
- Listado: cursor `(fecha_ot, id)`, filtros por código, cliente, estado, sector, responsable y rango
  de fechas. El servicio limita tamaño de página y no carga toda la colección.
- Todo índice candidato se valida con `EXPLAIN (ANALYZE, BUFFERS)` sobre volumen representativo antes
  de promoverlo; no se agrega `pg_trgm` sin evidencia.

## Initial Data

Seeds idempotentes por códigos estables:

- roles: ADMINISTRADOR, USUARIO;
- ESTADO_OT: PENDIENTE, EN_PROCESO, TERMINADO, ANULADO;
- sectores: DISENO(1), PRENSA(2), PRE_ACABADO(3), PRODUCCION(4), ALMACEN(NULL/no flujo);
- COLORIMETRIA: FULL_COLOR, PANTONE, FULL_MAS_PANTONE;
- IMPRESION: TIRO_Y_VOLTEO, TIRA_Y_RETIRA, CAMBIO_DE_PINZA;
- MUESTRARIO: APROBACION_COLOR_CLIENTE_MAQUINA, PRUEBA_COLOR, MUESTRA_FISICA, MUESTRA_DIGITAL,
  IMPRESION_ESCRITORIO;
- TIPO_TRABAJO: AFICHES, TARJETAS, CENEFAS, HOJAS, CUADERNOS, CATALOGOS, VIBRINES;
- ACABADO: PERFORADO, ENGOMADO, ANILLADO, ENGRAMPADO.

No se agregan catálogos no aprobados. La carga inicial del primer ADMINISTRADOR es un procedimiento
privilegiado separado del seed de negocio.
